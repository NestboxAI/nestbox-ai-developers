This page describes all commands available in the <CliCommand /> CLI for managing project configuration. Projects define the default context used for most CLI operations, such as deploying agents or managing compute instances.

Each project setting is stored locally and can be associated with a specific directory via a <code>.<CliCommand />rc</code> file.


## Set Active Project

Use this command to define which project the CLI should use by default in the current directory.

<pre>
  <code className="language-bash">
    {`${config.cliCommand} project use <project-name>`}
  </code>
</pre>

This will create or update a <code>.<CliCommand />rc</code> file in the current folder with the following format:

```json
{
  "projects": {
    "default": "<project-name>"
  }
}
```

## Add a Named Project Alias

You can define multiple project aliases, which allows you to quickly switch between environments (e.g., staging, production).

<pre>
  <code className="language-bash">
    {`${config.cliCommand} project add <project-name> alias=<alias>`}
  </code>
</pre>

For example:

<pre>
  <code className="language-bash">
    {`${config.cliCommand} project add sales-123 alias=prod`}
  </code>
</pre>

This updates <code>.<CliCommand />rc</code> with:

```json
{
  "projects": {
    "default": "project-name",
    "prod": "sales-123"
  }
}
```

## How Project Context Is Used

When a command requires a project context, the CLI will look for a <code>.<CliCommand />rc</code> file in the current directory or parent directories. If no project is configured and none is specified via <code>--project</code>, the CLI will display an error.

You can always override the default by passing a specific project ID:

<pre>
  <code className="language-bash">
    {`${config.cliCommand} agent deploy <agent-id> --project my-project`}
  </code>
</pre>
