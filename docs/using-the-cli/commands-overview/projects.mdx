This page describes all commands available in the <SiteName /> CLI for managing project configuration. Projects define the default context used for most CLI operations, such as deploying agents or managing compute instances.

## List Projects

List all available projects:

<pre>
  <code className="language-bash">
    {`${config.cliCommand} project list`}
  </code>
</pre>

Shows all projects from the API with their names, aliases (if any), and indicates which is the current default project.

## Set Active Project

Use this command to define which project the CLI should use by default:

<pre>
  <code className="language-bash">
    {`${config.cliCommand} project use <project-name>`}
  </code>
</pre>

**Parameters:**
- `<project-name>` – Name of the project to set as default

**Example:**

<pre>
  <code className="language-bash">
    {`${config.cliCommand} project use my-ai-project`}
  </code>
</pre>

## Add a Project

Add a project with an optional alias:

<pre>
  <code className="language-bash">
    {`${config.cliCommand} project add <project-name> [alias]`}
  </code>
</pre>

**Parameters:**
- `<project-name>` – Name of the project to add
- `[alias]` – Optional alias for the project

**Example:**

<pre>
  <code className="language-bash">
    {`${config.cliCommand} project add my-ai-project myproj`}
  </code>
</pre>

## How Project Context Is Used

When a command requires a project context, the CLI will look for a <code>.<CliCommand />rc</code> file in the current directory or parent directories. If no project is configured and none is specified via `--project`, the CLI will display an error.

You can always override the default by passing a specific project ID:

<pre>
  <code className="language-bash">
    {`${config.cliCommand} agent deploy --agent <agent-name> --project my-project`}
  </code>
</pre>
